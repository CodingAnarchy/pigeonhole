### Fixed
- Under a heavy write load with background compactions, most of a shard's memtable arena could sit unusable in memtables that were already flushed. A running compaction kept the whole read view, so every memtable live when it started stayed referenced until it ended. Writes then waited for room far more often than the load needed. A compaction now keeps only the SSTs it reads; an IVF memory store at 16 writers went from 5.8K to 8.2–9.6K memories/s on a 16-core machine (#1477).
