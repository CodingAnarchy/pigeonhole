### Added
- A feed of every table (`Pigeonhole::feed()`) delivers catalog changes (a table created with its families, a family added, a table dropped), each in its place among the commits: `Feed::next_event`, `try_next_event` and `poll_next_event` return a `FeedEvent`, and `nonblocking::FeedEventStream` is their `Stream` (D315, #1436). `next` and the other commits-only calls pass the catalog changes over. A feed opened now or from a snapshot starts after the changes it already sees, and a token resumes just past the last event. The sidecar's catalog record (type 4, new in this release) carries the names of the tables it changes, so a dropped table is still named. Internal crates take a breaking change (`Next::Catalog`, `FeedStart::Snapshot`).
