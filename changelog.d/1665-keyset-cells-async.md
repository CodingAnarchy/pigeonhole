### Fixed
- **Async reads over a key set no longer read a long row's later blocks synchronously** (#1665, #1652, ICR 0124). The multi-get's `next_async`, `Traverse::run_async` and `Nearest::run_async`, over keys and over a scan, now fetch every block a row's cells need without blocking, so a row longer than a block no longer reads on the polling thread. A sync `next` after an async fill that stopped mid-row finishes that row.
