### Added
- `phdb serve` clusters serve change feeds (D317 ticket 7, ICR 0117). `Feed.Subscribe` through any node follows every partition the subscription's tables (and prefix) cover, merged into one stream, each partition's commits in order. Each event names its `partition`. Tokens come as checkpoints, about 150 bytes of token per event on average; a resume from the last one may repeat the commits after it, which a client drops by `(partition, seqno)` or names in `skip_through`. `allow_partial` keeps a stream going without an unreachable partition, reported in `PartitionState` events, and picks it up again where it left off. `checkpoint_every` sets how often tokens come. A cluster node takes `--change-feed` for its partition.
