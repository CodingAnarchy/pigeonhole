### Fixed
- `pigeonhole-vector`: a split no longer reads a list whole. A list of any length (a bulk load whose vectors mostly fell in one list, or writes while a background rebalancer was behind) was read into memory whole by its split, and phase 2 read each neighbour whole; now a list past four list rows' worth of vectors (16 MiB of `f32`, or four split lengths if that's more) is split from a sample and moved a page per transaction, and phase 2 reads such a neighbour that much at a time, so a split holds at most that (#1824). A shorter list is still split in one transaction (#1879). `phdb serve`'s rebalance after a `Vectors.BulkLoad` no longer needs memory outside `--bulk-load-bytes` for a skewed load.
