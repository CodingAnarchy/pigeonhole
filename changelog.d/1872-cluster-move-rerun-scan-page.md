### Fixed
- **A scan of a table with aggregate families no longer ends early when a write lands between a page's two reads** (#1848). A page cut by its aggregate views is read a second time, with or without an aggregate query, and the second read now uses the same snapshot as the first. Before, it could come back empty with a position, which ended the scan's stream; a MultiGet answered no rows with `next` set.
- **`phdb cluster move` and `phdb cluster restore`, run again after an interrupted install on the new node, finish it** (#1848, ICR 0117 amendment). `Admin.PartitionUploadStatus` takes a new `partition` field and answers `installing` while that partition's install is in progress. A rerun then sends nothing and goes on to the stamp, which finishes the install. An upload is also complete only while its staged file is there, so a move run again after a stop at the end of an install no longer says "installed nothing" every time.
- **A cluster feed subscription with `allow_partial` keeps going when one of its partitions closes while a part of it subscribes** (#1848). That part ends with `PartitionUnavailable`, which the subscription waits out, instead of the closing database's error.
