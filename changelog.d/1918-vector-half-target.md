### Fixed
- **A new `f16` or `bf16` vector index sizes its lists for two bytes a dimension** (#1882). The target list length is scaled down so a list at its split length fits a 4 MiB row, but half-precision vectors were counted at one byte a dimension, so above about 1,000 dimensions their lists could grow to 8 MiB rows before splitting. An index keeps the options it was created with, so an existing half-precision index is unchanged; its larger rows cost larger reads, not errors. A new half-precision index above about 1,048 dimensions has lists half as long as one created before, so a search at the same `nprobe` examines about half as many vectors and its recall is lower: raise `nprobe` (doubling it probes as many vectors as before) to match an older index's recall.
