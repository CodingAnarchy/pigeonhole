### Added
- **`Options::wal_pad_unit(bytes)`: a GroupSync commit group no longer waits for the previous group's sync to finish writing back the WAL's last page** (#1708, D327, ICR 0137). With a unit set (4,096 is the usual choice), a group that would start in the page a sync is still writing starts at the next unit boundary instead, behind padding. That removes the write stalls of several milliseconds a busy disk could add to every shard at once (#1621). It costs WAL bytes, at most one pad per sync. Off by default until it has been measured. **The first open with it set flags the database so that builds before 1.3 refuse to open it**, and the flag stays.
