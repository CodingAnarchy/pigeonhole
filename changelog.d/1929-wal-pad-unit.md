### Added
- **`Options::wal_pad_unit(bytes)`: a GroupSync commit group no longer waits for the previous group's sync to finish writing back the WAL's last page** (#1708, D327, ICR 0137). With a unit set (4,096 is the usual choice), a group that would start in the page a sync is still writing starts at the next unit boundary instead, behind padding. That removes the write stalls of several milliseconds a busy disk could add to every shard at once (#1621). It costs WAL bytes, at most one pad per sync. `phdb serve --wal-pad-unit BYTES` sets it for every database the server opens. Off by default until it has been measured. **The first open with it set flags the database so that builds before 1.3 refuse to open it**, and the flag stays.

### Fixed
- **A durable change feed no longer expires spuriously after a power loss when its token was taken just past a skipped WAL frame tail** (#1937). A token resumed after the power loss and the recovery could expire with "records the feed read were lost" though nothing it delivered was lost; for a replica following a durable feed that meant a full re-bootstrap. A token's position for a stream is now the end of the record before, not the start of the next record's first fragment.
