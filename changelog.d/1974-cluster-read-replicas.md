### Added
- `phdb serve` clusters: a partition can have read replicas (D328, #1851). List their nodes in the partition's `replicas` in the map (`phdb cluster set-map`), and each holds a copy that downloads the partition from its owner and follows the owner's change feed, which must be on (`--change-feed`). The owner feeds a replica only while it holds the partition's lease. A copy keeps following after `phdb cluster move` or `relocate --copy`, and copies the partition again after a relocate without `--copy` or a restore. `phdb cluster status`, `Admin.Info` and `/metrics` report each copy's state and lag. Replicas don't serve reads yet, and none can be promoted: both come in later releases of this work. A `move`, `relocate` or `restore --partition` onto a node holding the partition's replica is refused for now, with the steps to do it.
