### Added
- `phdb serve` on a cluster: `Text.Search` runs across a text index's partitions and returns the hits and scores one index holding every document would (#1722, ICR 0138). It takes two rounds: every partition's statistics for the query, merged, then each partition `id_prefix` meets ranks with them. A search needs every partition of its index, so it fails with `PartitionUnavailable` (or `Unavailable` while a partition's index is still filling), unless it sets the new `allow_partial`. In that case it scores with the partitions that answered (`partial`) and names the ranges it skipped (`missing`). The new `TextSearchResponse.cut_clauses` names the fuzzy clauses whose expansions were cut at `max_expansions`, on a single node too.
