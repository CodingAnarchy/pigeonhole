### Changed
- **`pigeonhole-memory` recalls at one snapshot read a namespace's memory count once** (#2043, #2040). A recall reads the namespace counter to choose between exact and IVF search. Until the database applies the counter's checkpoint, each read folds every increment since the last one: about 6% of a recall for 2,000 memories. A recall at the same snapshot as an earlier one now reuses that recall's count, so many recalls after a bulk `remember` fold once. Any commit makes the next recall read the counter again, so results are unchanged. A reader process reads it every time, as before.
