### Changed
- **`phdb serve --embed-local` warns at startup while candle's thread-pool variables are unset** (#2061). The local embedding model's runtime (candle) runs large steps on a process-wide pool of its own, which `CANDLE_NUM_THREADS` sizes (else `RAYON_NUM_THREADS`, the mask's CPU count, or the physical cores) and, on Linux, only `CANDLE_CPU_MASK` places. Unset, its threads can run on the shards' CPUs, and on Linux it re-reads `/proc/cpuinfo` on every matrix product. The warning names the exact `export` line (the old advice came only with the shards pinned), and a new gauge, `pigeonhole_serve_embed_env_unset{variable}`, reads 1 for each variable the server started without. The serve guide has a new "Embedding placement" section. In `pigeonhole-embed`, `LoadOptions::threads`' doc now says it doesn't bound candle's own pool.
