### Added
- **Range moves and splits run end to end** (D331, #1499): `phdb cluster move-range TABLE --from S --to T` moves a key range of a table to another partition while both serve, and `phdb cluster split TABLE --from S --key K --to N` moves `S`'s range from `K` into a new partition created empty on node `N`. The new partition's id is `S-<v>` (v the map version that records the split), or `--id`.
  - Each phase is recorded in the map: COPYING, CATCHING_UP, HANDING_OVER, HANDED_OVER (the commit point), CLEANING. Running the command again, or `move-range --resume ID`, goes on from there; `move-range --abort ID` ends a move or split before its commit point.
  - A move is planned first against the source node's `--move-rate-bytes`, `--move-retention-cap` and `--max-move-followers`; `--skip-fit-check` starts one the whole-partition estimate says won't fit. `phdb cluster status` (`NodeStatus`) reports a node's three limits.
  - Failover and `phdb cluster promote` are refused for either partition of a range move from its hand-over until it ends.
