### Fixed
- **A change feed started from the oldest history no longer skips a spanning transaction that was in doubt across a restart** (#2190). A feed started `from_oldest` after a reopen could begin in an earlier session that opened with an externally prepared transaction (a `phdb serve` spanning transaction's share) still in doubt. It then passed over that transaction's commit without delivering it or reporting an error. Such a start now begins in a later session, or at the current one, so it delivers the commit or expires. Databases that never logged an external PREPARE skip the extra read this takes.
- **A token taken from an expired change feed no longer resumes past the gap** (#2196). A token taken after a feed ended with `FeedExpired` on a spanning transaction's commit resumed after that commit, with no error, so the commit was never delivered. Such a token now resumes before it and expires again. Starting `from_oldest` again also expires again until retention passes the commit. To recover, rebuild from a snapshot and start `from_snapshot`, as the change-feed guide says.
