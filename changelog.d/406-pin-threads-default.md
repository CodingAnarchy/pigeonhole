### Changed
- Engine-owned shard and compaction threads are pinned to CPUs of their own by default (`Options::pin_threads`, D235): inside the opening thread's affinity set, one per physical core first. Opens never fail because of pinning: threads run unpinned on macOS, under a CPU quota narrower than the affinity set, or when too few CPUs are free, and several databases in one process pin to different CPUs. `EngineMetrics::{pinned_threads, unpinned}` report it. Several processes on one host should each get their own CPUs (an affinity mask or cpuset) or use `pin_threads(false)`.
