### Added
- `Shard::wait(timeout)` and `Shard::waker()` for application-owned mode (#553, ICR 0035). `wait` blocks the driving thread until the shard has work again: a commit or message arrives, a `waker()` wake, the thread's own I/O completes, background work falls due, or the timeout passes. It works on every backend with no file descriptor, so a loop that runs `run_once` until idle and then calls `wait` no longer busy-polls on io_uring. Give the futures the driving thread polls `shard.waker()`. `next_wakeup`, `io_fd` and `set_wakeup` remain for applications with their own event loop.
