### Changed
- **The default shard count is one per physical core** the process may run on, not one per logical CPU (D220): SMT siblings count once, and a cgroup CPU quota still caps it. On the reference machine (16 cores, 32 threads), 16 shards gave twice the long-run durable group-commit throughput of 32 (4.5M against 2.2M cells/s) and met the p99 target. Linux reads the sysfs topology of the CPUs in the affinity mask, macOS asks `hw.physicalcpu`, and Windows asks `GetLogicalProcessorInformation`; elsewhere the default is the available CPUs, as before. `Options::shards(n)` still sets it.
- With `Options::pin_threads(true)`, shard `i` is pinned to the `i`-th physical core's first CPU, then to the cores' SMT siblings, rather than to the `i`-th CPU: default-count shards never share a core, however the CPUs are numbered.
