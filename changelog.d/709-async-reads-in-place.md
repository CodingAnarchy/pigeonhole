### Changed
- An async read (`read_async`, `get_async`, async scans) that misses the block cache but finds the block in the OS page cache now reads it in place and carries on, as a synchronous read does. Previously, it abandoned the read, fetched the block, and ran the whole read again for every block it missed. A read that must wait on the device still returns a future, and that future resumes the read already submitted rather than submitting it again. Results are unchanged. On the benchmark's read-only YCSB C with 16 client threads keeping 16 reads each in flight, async throughput is up by (box A/B pending) (#709).
