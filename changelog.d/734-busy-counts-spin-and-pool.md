### Fixed
- Tablet packing now counts the time a shard thread spends polling for its next message before it parks, and the time the compaction pool's threads spend on the shard's own flushes and compactions, beside the thread's work time (D256). A heavy write load spread over every shard read as nearly idle once flush and compaction left the shard threads (D252), so packing moved every tablet onto two shards and then back out again as they saturated, which showed as a put latency tail at the start of each run (#734). A growth from a saturated shard now also holds the active shard count while the write rate holds, as a growth from a stalling shard already did (D255). `ShardStats` and `Metrics` report the two new counters beside `busy_nanos`.
