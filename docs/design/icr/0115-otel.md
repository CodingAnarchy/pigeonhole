# 0115: `pigeonhole-otel`, and the public commit-latency histogram

**Status:** Approved. The coordinator assigned the number (2026-11-04), and the owner settled Q1 and Q2 on #1458 the same day. The design is D316, reviewed by perf287 (hot path) and cli692 (API and docs).

## The change
- **`pigeonhole-otel`, a new crate** on its own 0.N version line, starting at 0.1.0 (D316 Q1):
  - **Registering:** `register(&Pigeonhole, &opentelemetry::metrics::Meter) -> Registration`, and `Config` (`new`, `db_name`, `storage_by_table`, `latency_window`, `register`). Both return values are `#[must_use]`.
  - **`Registration`:** `rebind(&Pigeonhole)`. Dropping it stops reporting.
  - **The metric list:** `metrics() -> impl ExactSizeIterator<Item = MetricInfo>`, where `MetricInfo` (`#[non_exhaustive]`) has `name`, `kind`, `unit`, `attributes` and `description`, plus `prometheus_name()`. `InstrumentKind` (`#[non_exhaustive]`) is `Counter` or `Gauge`.
  - **The contract:** the metrics and their names, kinds, units and attributes are D316's.
- **pigeonhole** (semver, additive):
  - `EngineMetrics::commit_latency(Durability) -> LatencyHistogram`: D213's commit-latency buckets, which were a hidden bench hook until now (A1).
  - `LatencyHistogram`: `BUCKETS` (64), `counts()`, `total()`, `bucket_lower_nanos(b)`, `bucket_upper_nanos(b) -> Option<u64>`, `since(&earlier)`, `quantile_upper_nanos(q) -> Option<u64>`, and `Default`.
  - `Pigeonhole::path()` and `PigeonholeReader::path()`: the path as given at open, not canonicalised (cli692). `pigeonhole-otel` names a database by its file name.
  - `Pigeonhole::is_closed()`: one atomic load. A registration whose database was closed reports nothing, and `info()` alone can't tell that, since it still answers after a close.
- **pigeonhole-engine** (internal, 2.x line, additive): `Metrics::commit_latency_buckets: [LatencyBuckets; 4]`, which `metrics()` already summed to get its percentiles, and the `LatencyBuckets` newtype.

## Why
#1458: applications export the engine's metrics through OpenTelemetry without writing a polling loop of their own. The existing `CommitStats` percentiles cover everything since open, so after an hour they hide a fresh regression. The histogram lets two readings give an interval's quantiles (D316 A1). Adding it costs the write path nothing: the buckets already exist, and `metrics()` already read them.

## Callers changed
None: everything is additive. `pigeonhole-otel` is the first caller of the four `pigeonhole` additions. `phdb serve`'s `/metrics` (D313, #1397) will reuse D316's names, and A1's buckets for a native histogram.
