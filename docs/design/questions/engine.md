# Engine questions

## Q: How does a write stall end, and how does failed background work back off, when the clock moves only with the caller (issues #70, #79)?
D119 cancels the L0 stall's timer when a compaction commits and D124 times a wait for arena room out after `write_stall_timeout_nanos`, but both lean on a clock. Under `SimVfs` the clock moves only when the workload advances it, and the workload is blocked in the commit (or, in application-owned mode, in `run_once`, whose slice deadline never comes). Three things followed: a `StallTimer` polling the clock spun for ever; a failed background compaction with an L0 score `>= 1.0` was retried at once by `maintain`, redoing the merge in a loop against a dead (crashed or poisoned) device (#79); and a stall that engaged with nothing running in the background had nothing to end it.

**Interim behavior:**
- A stall never busy-spins: a `StallTimer` that sees the clock unchanged for 1024 polls in a row gives up (it is only a shortcut for a running clock); the shard arms a new one at the next event that finds it still stalled.
- The L0 stall engages only while a compaction is running (the stall starts one if none runs; when none can start, writers are admitted). Every compaction completion, success or failure, kicks a waiting group, and a successful one adds a token to the bucket: on a frozen clock the stall is paced by compaction progress instead of time.
- After a failed background compaction, `maintain` starts none until a flush completes or a group is admitted (the old rule retried at once while the score was `>= 1.0`): each retry is tied to a foreground event, never to the clock, so a dead device does not loop and a stalled writer is admitted rather than held (and then fails with the store's error). A poisoned shard starts no background compaction until reopen.
- A wait for arena room ends with `Busy` after 4 flushes in a row failed (a frozen clock never reaches the timeout), and at once when nothing the shard would hear of can free room: no flush running or queued, no deferred freeze, no undecided share and no unsynced group (what is left is held by snapshots). A poisoned pager still fails it with the poison error at once. The members a group admitted before the cut still apply (the timeout path used to drop them).
- `reserve_room` reclaims retired memtables whose readers left before it reports no room.
